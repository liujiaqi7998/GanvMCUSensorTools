# 使用者文件：序列埠通訊使用說明

## 1. 文件目的

本文提供給上位機、PLC、微控制器及工業控制主機的整合開發者，說明如何透過序列埠與 8 通道顏色對比感測器通訊，讀取裝置資料並解析回傳欄位。



## 2. 產品的序列埠功能

透過序列埠，主機可以完成以下操作：

- 檢測裝置是否在線上。
- 視需要查詢 8 通道感測器資料。
- 查詢裝置基本資訊及已儲存的校正資料。
- 擷取底色、線色並儲存校正結果。
- 重新啟動裝置。
- 啟動或停止即時資料串流。
- 辨識裝置回傳的錯誤回應。

## 3. 序列埠參數

| 項目 | 參數 |
| --- | --- |
| 通訊方式 | UART 序列埠 |
| 鮑率 | `115200` |
| 資料位元 | `8 bit` |
| 同位檢查 | 無 |
| 停止位元 | `1 bit` |
| 硬體流量控制 | 無 |
| 常用表示 | `115200 8N1` |

## 4. 通訊方式概覽

序列埠通訊包含三種形式：

1. **PING 通訊**：主機傳送 `CC`，裝置回傳 `CC`，用於快速確認連線。
2. **標準請求/回應訊框**：主機傳送 `AA ... BB` 格式的請求訊框，裝置回傳相同結構的回應訊框。
3. **即時資料串流**：主機傳送即時串流控制位元組後，裝置依週期輸出固定長度的資料訊框。

若只需偶爾讀取一次資料，建議使用「感測器資料查詢」。若需持續更新資料，建議使用「即時資料串流」。

## 5. PING 通訊

PING 用於確認裝置在線上和序列埠連線可用。

### 5.1 請求

```text
CC
```

### 5.2 回應

```text
CC
```

### 5.3 說明

- PING 是單一位元組通訊，不使用標準訊框格式。
- 主機傳送 `0xCC` 後，裝置正常在線上時回傳 `0xCC`。

## 6. 標準訊框格式

標準訊框用於請求/回應類命令。請求訊框與回應訊框的結構相同。

```text
AA Command Length Payload CRC_L CRC_H BB
```

| 順序 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 1 | 訊框起始位元組 | 1B | 固定為 `0xAA`，表示標準訊框開始 |
| 2 | Command | 1B | 命令碼，表示目前訊框的功能類型 |
| 3 | Length | 1B | Payload 的位元組數 |
| 4 | Payload | N 位元組 | 負載資料，長度由 Length 指定 |
| 5 | CRC_L | 1B | CRC-16 低位元組 |
| 6 | CRC_H | 1B | CRC-16 高位元組 |
| 7 | 訊框結尾位元組 | 1B | 固定為 `0xBB`，表示標準訊框結束 |

### 6.1 Length 欄位

`Length` 只表示 `Payload` 的長度，不包含訊框起始位元組、命令碼、Length 本身、CRC 及訊框結尾位元組。

例如：

```text
AA 01 00 00 20 BB
```

意義：

| 位元組 | 意義 |
| --- | --- |
| `AA` | 訊框起始位元組 |
| `01` | 命令碼：感測器資料查詢請求 |
| `00` | Payload 長度為 0 |
| `00 20` | CRC-16，低位元組在前 |
| `BB` | 訊框結尾位元組 |

## 7. CRC-16 檢查

標準訊框使用 CRC-16 檢查。

| 項目 | 說明 |
| --- | --- |
| 算法 | CRC-16/MODBUS |
| 初始值 | `0xFFFF` |
| 多項式 | `0xA001` |
| 輸出位元組順序 | 低位元組在前，高位元組在後 |
| 計算範圍 | `Command + Length + Payload` |

CRC 不包含：

- 訊框起始位元組 `0xAA`
- CRC 欄位本身
- 訊框結尾位元組 `0xBB`

## 8. 快速開始

### 8.1 檢查裝置是否在線上

主機傳送：

```text
CC
```

裝置回傳：

```text
CC
```

### 8.2 查詢一次感測器資料

主機傳送標準訊框：

```text
AA 01 00 00 20 BB
```

裝置回傳命令碼為 `0x81` 的標準訊框，Payload 長度為 20 位元組。

### 8.3 啟動即時資料串流

主機傳送：

```text
DD 0A
```

表示啟動即時資料串流，其中 `Interval` 為 1 位元組輸出間隔，單位為毫秒；`0x0A` 表示每 10 ms 輸出一次。

### 8.4 停止即時資料串流

主機傳送：

```text
DD 00
```

表示停止即時資料串流。

## 9. 感測器資料查詢

感測器資料查詢用於讀取 8 通道數位輸出、類比值、正規化值及偏移量。

### 9.1 請求

| 項目 | 值 |
| --- | --- |
| Command | `0x01` |
| Length | `0x00` |
| Payload | 無 |

完整請求範例：

```text
AA 01 00 00 20 BB
```

### 9.2 回應

| 項目 | 值 |
| --- | --- |
| Command | `0x81` |
| Length | `0x14`，即 20 位元組 |
| Payload | 感測器資料 |

Payload 欄位定義：

| 偏移量 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 0 | Status | 1B | 狀態位元圖，意義見下表 |
| 1 | Digital | 1B | 8 通道數位輸出位元圖 |
| 2-9 | Analog | 8B | 8 通道類比值，每通道 1 位元組 |
| 10-17 | Normal | 8B | 8 通道正規化值，每通道 1 位元組 |
| 18-19 | Offset | 2B | 偏移量，有號 16 位元整數，低位元組在前 |

`Status` 各位意義：

| 位或數值 | 意義 |
| --- | --- |
| bit0 = `1` | 目前探頭過度曝光 |
| bit1 = `1` | 校正鎖定：先前校正出錯，目前無法進入校正狀態，如需退出，請重新啟動裝置 |
| `0x00` | 未檢測到上述狀態 |

### 9.3 Digital 欄位

`Digital` 是 8 通道數位輸出位元圖。

| bit | 通道 |
| --- | --- |
| bit0 | 通道 0 |
| bit1 | 通道 1 |
| bit2 | 通道 2 |
| bit3 | 通道 3 |
| bit4 | 通道 4 |
| bit5 | 通道 5 |
| bit6 | 通道 6 |
| bit7 | 通道 7 |

範例：

```text
Digital = 05
```

`0x05` 的二進位為 `0000 0101`，表示通道 0 和通道 2 的輸出為 1。

### 9.4 Analog 欄位

`Analog` 為 8 位元組，依序表示通道 0 到通道 7 的類比值。

| 位元組位置 | 通道 |
| --- | --- |
| Analog[0] | 通道 0 |
| Analog[1] | 通道 1 |
| Analog[2] | 通道 2 |
| Analog[3] | 通道 3 |
| Analog[4] | 通道 4 |
| Analog[5] | 通道 5 |
| Analog[6] | 通道 6 |
| Analog[7] | 通道 7 |

### 9.5 Normal 欄位

`Normal` 為 8 位元組，依序表示通道 0 到通道 7 的正規化值。

| 位元組位置 | 通道 |
| --- | --- |
| Normal[0] | 通道 0 |
| Normal[1] | 通道 1 |
| Normal[2] | 通道 2 |
| Normal[3] | 通道 3 |
| Normal[4] | 通道 4 |
| Normal[5] | 通道 5 |
| Normal[6] | 通道 6 |
| Normal[7] | 通道 7 |

### 9.6 Offset 欄位

`Offset` 是 2 位元組資料。解析時，先依小端序將兩個位元組組合成一個 16 位元值，再將該值解讀為 signed int16。

範例：

| 原始位元組 | 解析結果 |
| --- | --- |
| `01 00` | `1` |
| `FF FF` | `-1` |
| `00 80` | `-32768` |

## 10. 裝置資訊查詢

裝置資訊查詢用於讀取硬體版本、裝置運作時間、軟體版本及板型。

### 10.1 請求

| 項目 | 值 |
| --- | --- |
| Command | `0x04` |
| Length | `0x00` |
| Payload | 無 |

完整請求範例：

```text
AA 04 00 03 70 BB
```

其中 `04 00` 的 CRC-16/MODBUS 計算結果為 `0x7003`，傳送時依低位元組在前、高位元組在後的順序寫入，因此 CRC 位元組為 `03 70`。

### 10.2 回應

| 項目 | 值 |
| --- | --- |
| Command | `0x84` |
| Length | `0x08`，即 8 位元組 |
| Payload | 裝置資訊 |

Payload 欄位定義：

| 偏移量 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 0 | HardwareVersion | 1B | 硬體版本號；`0xFF` 表示未寫入或無效 |
| 1-4 | RuntimeSeconds | 4B | 本次通電後的運作時間，單位為秒，低位元組在前 |
| 5 | RunMode | 1B | 目前運作模式 |
| 6 | SoftwareVersion | 1B | 軟體版本號 |
| 7 | BoardType | 1B | 板型 |

`RunMode` 定義：

| 值 | 意義 |
| --- | --- |
| `0x00` | 正常運作 |

硬體版本和軟體版本的高 4 位元表示主版本、低 4 位元表示次版本，例如 `0x21` 表示 `2.1`。目前韌體的軟體版本位元組為 `0x37`，即 `3.7`。`BoardType` 為 `0x00` 時表示弓形板，為 `0x01` 時表示直形板。

## 11. 校正資料與校正操作

校正時，先讓感測器對準底色並擷取，再對準線色並擷取，最後儲存。擷取命令讀取傳送命令當下的測量值。

### 11.1 查詢已儲存的校正資料

傳送命令 `0x05`，請求 Payload 為空：

```text
AA 05 00 02 E0 BB
```

裝置回傳命令 `0x85`，Payload 長度為 33 位元組：

| 偏移量 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 0-15 | High[0..7] | 16B | 8 通道高值校正資料，每通道 2 位元組，小端序 |
| 16-31 | Low[0..7] | 16B | 8 通道低值校正資料，每通道 2 位元組，小端序 |
| 32 | LineType | 1B | `0x00`：底色為高值、線色為低值；`0x01`：底色為低值、線色為高值 |

### 11.2 擷取底色

讓感測器對準底色後，傳送命令 `0x06`：

```text
AA 06 00 02 10 BB
```

成功時裝置回傳命令 `0x86`、Payload 長度 `0x01`，Payload 為 `00`。若目前過度曝光或校正已鎖定，則回傳錯誤碼 `0x05`。

### 11.3 擷取線色

讓感測器對準線色後，傳送命令 `0x07`。可一次擷取全部 8 通道，也可以分兩次擷取：

| 擷取範圍 | 完整請求訊框 |
| --- | --- |
| 全部 8 通道 | `AA 07 00 03 80 BB` |
| 前 4 通道（通道 0-3） | `AA 07 01 01 00 51 BB` |
| 後 4 通道（通道 4-7） | `AA 07 01 02 40 50 BB` |

直形板可一次擷取全部 8 通道。弓形板先擷取前 4 通道，再擷取後 4 通道；若只完成其中一次，便無法儲存。帶 1 位元組 Payload 的 `00` 也表示擷取全部 8 通道。

成功時裝置回傳命令 `0x87`、Payload 長度 `0x01`，Payload 為 `00`。擷取時過度曝光或校正已鎖定回傳錯誤碼 `0x05`；範圍值無效回傳 `0x03`。

### 11.4 儲存校正資料

完成底色和全部線色擷取後，傳送命令 `0x08`：

```text
AA 08 00 06 70 BB
```

成功時裝置回傳命令 `0x88`、Payload 長度 `0x01`，Payload 為 `00`。擷取不完整回傳錯誤碼 `0x03`；校正已鎖定回傳 `0x05`。儲存後可再次傳送 `0x05` 查詢校正資料。

## 12. 重新啟動裝置

傳送命令 `0x10`，Payload 為 `01`：

```text
AA 10 01 01 B0 55 BB
```

裝置先回傳命令 `0x90`、Payload `00 01`，隨後重新啟動。重新啟動期間序列埠會短暫無法使用，待裝置重新就緒後可傳送 PING。

## 13. 即時資料串流

即時資料串流用於讓裝置定期主動輸出感測器資料。

即時資料串流不使用標準訊框格式，而是使用固定長度的資料訊框。

### 13.1 啟動或更新即時資料串流

主機傳送：

```text
DD Interval
```

| 位元組 | 說明 |
| --- | --- |
| `DD` | 即時串流控制起始位元組 |
| `Interval` | 1 位元組輸出間隔，單位為毫秒；非零表示啟動或更新即時輸出週期，`00` 表示停止串流輸出 |

範例：

```text
DD 0A
```

表示啟動即時資料串流，輸出間隔為 10 ms。

### 13.2 停止即時資料串流

主機傳送：

```text
DD 00
```

`Interval` 為 `0x00` 時，裝置停止即時資料串流。即時串流啟動期間，裝置不會處理一般查詢和校正請求；傳送這些請求前，先傳送 `DD 00` 停止即時串流。

### 13.3 即時資料訊框格式

裝置輸出固定長度 21 位元組資料訊框：

```text
DD Digital Analog[0] ... Analog[7] Normal[0] ... Normal[7] Offset_L Offset_H EE
```

| 偏移量 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 0 | 訊框起始位元組 | 1B | 固定為 `0xDD` |
| 1 | Digital | 1B | 8 通道數位輸出位元圖 |
| 2-9 | Analog | 8B | 8 通道類比值，每通道 1 位元組 |
| 10-17 | Normal | 8B | 8 通道正規化值，每通道 1 位元組 |
| 18-19 | Offset | 2B | 偏移量，有號 16 位元整數，低位元組在前 |
| 20 | 訊框結尾位元組 | 1B | 固定為 `0xEE` |

### 13.4 即時資料串流解析注意事項

- 即時資料訊框長度固定為 21 位元組。
- 即時資料訊框沒有 Command、Length 和 CRC 欄位。
- 解析即時串流時，應尋找訊框起始位元組 `0xDD` 和訊框結尾位元組 `0xEE`，並確認長度為 21 位元組。
- 即時串流中的 `Digital`、`Analog`、`Normal`、`Offset` 欄位意義與感測器資料查詢回應中的同名欄位一致。

## 14. 錯誤回應

當裝置收到不支援的命令、長度錯誤、參數錯誤，或校正時出現過度曝光時，可能回傳錯誤回應。

錯誤回應使用標準訊框格式。

| 項目 | 值 |
| --- | --- |
| Command | `0x7F` |
| Length | `0x02` |
| Payload | 原始命令碼 + 錯誤碼 |

Payload 欄位定義：

| 偏移量 | 欄位 | 長度 | 說明 |
| --- | --- | --- | --- |
| 0 | OriginCommand | 1B | 觸發錯誤的原始命令碼 |
| 1 | ErrorCode | 1B | 錯誤碼 |

錯誤碼定義：

| 錯誤碼 | 意義 |
| --- | --- |
| `0x01` | 不支援的命令 |
| `0x02` | 資料長度錯誤 |
| `0x03` | 參數值錯誤 |
| `0x04` | 執行失敗 |
| `0x05` | 校正擷取時過度曝光，或校正已鎖定 |

範例：

```text
Command = 7F
Payload = 99 01
```

表示命令 `0x99` 不受支援。

## 15. 欄位與位元組順序說明

### 15.1 十六進位表示

本文中的位元組均使用十六進位表示。例如：

```text
AA 01 00 00 20 BB
```

表示依序傳送 6 個位元組：`0xAA`、`0x01`、`0x00`、`0x00`、`0x20`、`0xBB`。

### 15.2 多位元組欄位

多位元組欄位採用小端序，即低位元組在前，高位元組在後。

例如 `Offset` 原始位元組為：

```text
34 12
```

解析為：

```text
0x1234
```

### 15.3 標準訊框解析建議

解析標準訊框時建議依照下列順序處理：

1. 尋找訊框起始位元組 `0xAA`。
2. 讀取 `Command`。
3. 讀取 `Length`。
4. 根據 `Length` 讀取指定長度的 `Payload`。
5. 讀取 2 位元組 CRC。
6. 確認訊框結尾位元組為 `0xBB`。
7. 對 `Command + Length + Payload` 計算 CRC，並與收到的 CRC 比對。
8. CRC 正確後，再依命令碼解析 Payload。

### 15.4 即時串流解析建議

解析即時資料串流時建議依照下列順序處理：

1. 尋找訊框起始位元組 `0xDD`。
2. 持續讀取 21 位元組。
3. 確認第 21 個位元組為訊框結尾位元組 `0xEE`。
4. 依固定偏移量解析 `Digital`、`Analog`、`Normal` 和 `Offset`。

## 16. 常見問題

### 16.1 為什麼傳送 `CC` 後沒有回傳？

請檢查：

- 序列埠編號是否正確。
- 鮑率是否為 `115200`。
- 資料格式是否為 `8N1`。
- TX/RX 是否接反。
- 裝置是否正常供電。

### 16.2 為什麼標準訊框沒有回應？

請檢查：

- 訊框起始位元組是否為 `AA`。
- 訊框結尾位元組是否為 `BB`。
- Length 是否等於 Payload 實際長度。
- CRC 是否依 `Command + Length + Payload` 計算。
- CRC 是否低位元組在前。

### 16.3 何時使用查詢，何時使用即時串流？

- 偶爾讀取一次資料：使用感測器資料查詢。
- 需要持續顯示或繪圖：使用即時資料串流。
- 需要確認裝置是否連線：使用 PING。
