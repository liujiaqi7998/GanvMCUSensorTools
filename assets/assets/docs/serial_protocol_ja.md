# ユーザーガイド：シリアル通信の使い方

## 1. この文書の目的

この文書は、上位システム、PLC、マイコン、産業用ホストの開発者向けに、シリアルポートを介して 8 チャンネルのカラーコントラストセンサーと通信し、デバイスのデータを読み取って応答フィールドを解析する方法を説明します。

## 2. シリアル通信でできること

ホストはシリアル通信で次の操作を行えます。

- デバイスがオンラインかどうかを確認する。
- 必要に応じて 8 チャンネルのセンサーデータを照会する。
- デバイスの基本情報と保存済みの校正データを照会する。
- 背景色とライン色を取得し、校正結果を保存する。
- デバイスを再起動する。
- リアルタイムデータストリームを開始または停止する。
- デバイスが返すエラー応答を識別する。

## 3. シリアルポートの設定

| 項目 | 設定値 |
| --- | --- |
| 通信方式 | UART シリアル通信 |
| ボーレート | `115200` |
| データビット | `8 bit` |
| パリティ | なし |
| ストップビット | `1 bit` |
| ハードウェアフロー制御 | なし |
| 一般的な表記 | `115200 8N1` |

## 4. 通信方式の概要

シリアル通信には次の 3 つの方式があります。

1. **PING 通信**：ホストが `CC` を送信すると、デバイスが `CC` を返します。接続をすばやく確認できます。
2. **標準要求・応答フレーム**：ホストが `AA ... BB` 形式の要求フレームを送信すると、デバイスが同じ構造の応答フレームを返します。
3. **リアルタイムデータストリーム**：ホストがストリーム制御バイトを送信すると、デバイスが一定周期で固定長のデータフレームを出力します。

データを時々 1 回だけ読み取る場合は「センサーデータ照会」、連続して更新する場合は「リアルタイムデータストリーム」を使用してください。

## 5. PING 通信

PING は、デバイスがオンラインでシリアル接続が利用できることを確認するために使用します。

### 5.1 要求

```text
CC
```

### 5.2 応答

```text
CC
```

### 5.3 説明

- PING は 1 バイトの通信であり、標準フレーム形式は使用しません。
- ホストが `0xCC` を送信すると、デバイスが正常にオンラインであれば `0xCC` を返します。

## 6. 標準フレーム形式

標準フレームは要求・応答型のコマンドに使用します。要求フレームと応答フレームの構造は同じです。

```text
AA Command Length Payload CRC_L CRC_H BB
```

| 順序 | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 1 | フレームヘッダー | 1B | 固定値 `0xAA`。標準フレームの開始を示します |
| 2 | Command | 1B | 現在のフレームのコマンド種別を示すコード |
| 3 | Length | 1B | Payload のバイト数 |
| 4 | Payload | N バイト | ペイロードデータ。長さは Length で指定します |
| 5 | CRC_L | 1B | CRC-16 の下位バイト |
| 6 | CRC_H | 1B | CRC-16 の上位バイト |
| 7 | フレーム終端 | 1B | 固定値 `0xBB`。標準フレームの終わりを示します |

### 6.1 Length フィールド

`Length` が示すのは `Payload` の長さだけです。フレームヘッダー、コマンドコード、Length 自体、CRC、フレーム終端は含みません。

例：

```text
AA 01 00 00 20 BB
```

各バイトの意味：

| バイト | 意味 |
| --- | --- |
| `AA` | フレームヘッダー |
| `01` | コマンドコード：センサーデータ照会要求 |
| `00` | Payload の長さは 0 |
| `00 20` | CRC-16。下位バイトが先 |
| `BB` | フレーム終端 |

## 7. CRC-16 チェック

標準フレームは CRC-16 でチェックします。

| 項目 | 説明 |
| --- | --- |
| アルゴリズム | CRC-16/MODBUS |
| 初期値 | `0xFFFF` |
| 多項式 | `0xA001` |
| 出力バイト順 | 下位バイトが先、上位バイトが後 |
| 計算対象 | `Command + Length + Payload` |

CRC の計算には次のものを含めません。

- フレームヘッダー `0xAA`
- CRC フィールド自体
- フレーム終端 `0xBB`

## 8. クイックスタート

### 8.1 デバイスがオンラインか確認する

ホストが送信：

```text
CC
```

デバイスが応答：

```text
CC
```

### 8.2 センサーデータを 1 回照会する

ホストが標準フレームを送信：

```text
AA 01 00 00 20 BB
```

デバイスは、コマンドコードが `0x81`、Payload の長さが 20 バイトの標準フレームを返します。

### 8.3 リアルタイムデータストリームを開始する

ホストが送信：

```text
DD 0A
```

リアルタイムデータストリームを開始します。`Interval` は 1 バイトの出力間隔で、単位はミリ秒です。`0x0A` は 10 ms ごとの出力を示します。

### 8.4 リアルタイムデータストリームを停止する

ホストが送信：

```text
DD 00
```

リアルタイムデータストリームを停止します。

## 9. センサーデータ照会

センサーデータ照会では、8 チャンネルのデジタル値、アナログ値、正規化値、オフセットを読み取ります。

### 9.1 要求

| 項目 | 値 |
| --- | --- |
| Command | `0x01` |
| Length | `0x00` |
| Payload | なし |

要求フレーム全体の例：

```text
AA 01 00 00 20 BB
```

### 9.2 応答

| 項目 | 値 |
| --- | --- |
| Command | `0x81` |
| Length | `0x14`（20 バイト） |
| Payload | センサーデータ |

Payload のフィールド定義：

| オフセット | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 0 | Status | 1B | 状態ビットマップ。意味は次の表を参照 |
| 1 | Digital | 1B | 8 チャンネルのデジタル出力ビットマップ |
| 2-9 | Analog | 8B | 8 チャンネルのアナログ値。各チャンネル 1 バイト |
| 10-17 | Normal | 8B | 8 チャンネルの正規化値。各チャンネル 1 バイト |
| 18-19 | Offset | 2B | オフセット。符号付き 16 ビット整数で、下位バイトが先 |

`Status` の各ビットの意味：

| ビットまたは値 | 意味 |
| --- | --- |
| bit0 = `1` | 現在、センサーヘッドが露出過多 |
| bit1 = `1` | 校正がロックされています。以前の校正でエラーが発生したため、現在は校正状態に入れません。解除するにはデバイスを再起動してください |
| `0x00` | 上記の状態は検出されていません |

### 9.3 Digital フィールド

`Digital` は 8 チャンネルのデジタル出力ビットマップです。

| bit | チャンネル |
| --- | --- |
| bit0 | チャンネル 0 |
| bit1 | チャンネル 1 |
| bit2 | チャンネル 2 |
| bit3 | チャンネル 3 |
| bit4 | チャンネル 4 |
| bit5 | チャンネル 5 |
| bit6 | チャンネル 6 |
| bit7 | チャンネル 7 |

例：

```text
Digital = 05
```

`0x05` を 2 進数で表すと `0000 0101` で、チャンネル 0 とチャンネル 2 の出力が 1 であることを示します。

### 9.4 Analog フィールド

`Analog` は 8 バイトで、チャンネル 0 からチャンネル 7 までのアナログ値を順に示します。

| バイト位置 | チャンネル |
| --- | --- |
| Analog[0] | チャンネル 0 |
| Analog[1] | チャンネル 1 |
| Analog[2] | チャンネル 2 |
| Analog[3] | チャンネル 3 |
| Analog[4] | チャンネル 4 |
| Analog[5] | チャンネル 5 |
| Analog[6] | チャンネル 6 |
| Analog[7] | チャンネル 7 |

### 9.5 Normal フィールド

`Normal` は 8 バイトで、チャンネル 0 からチャンネル 7 までの正規化値を順に示します。

| バイト位置 | チャンネル |
| --- | --- |
| Normal[0] | チャンネル 0 |
| Normal[1] | チャンネル 1 |
| Normal[2] | チャンネル 2 |
| Normal[3] | チャンネル 3 |
| Normal[4] | チャンネル 4 |
| Normal[5] | チャンネル 5 |
| Normal[6] | チャンネル 6 |
| Normal[7] | チャンネル 7 |

### 9.6 Offset フィールド

`Offset` は 2 バイトのデータです。解析時には、まず 2 バイトをリトルエンディアンで 16 ビット値に結合し、その値を符号付き int16 として解釈します。

例：

| 元のバイト | 解析結果 |
| --- | --- |
| `01 00` | `1` |
| `FF FF` | `-1` |
| `00 80` | `-32768` |

## 10. デバイス情報照会

デバイス情報照会では、ハードウェアバージョン、デバイスの稼働時間、ソフトウェアバージョン、基板の種類を読み取ります。

### 10.1 要求

| 項目 | 値 |
| --- | --- |
| Command | `0x04` |
| Length | `0x00` |
| Payload | なし |

要求フレーム全体の例：

```text
AA 04 00 03 70 BB
```

`04 00` の CRC-16/MODBUS の計算結果は `0x7003` です。送信時は下位バイト、上位バイトの順に書き込むため、CRC バイトは `03 70` になります。

### 10.2 応答

| 項目 | 値 |
| --- | --- |
| Command | `0x84` |
| Length | `0x08`（8 バイト） |
| Payload | デバイス情報 |

Payload のフィールド定義：

| オフセット | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 0 | HardwareVersion | 1B | ハードウェアバージョン番号。`0xFF` は未書き込みまたは無効を示します |
| 1-4 | RuntimeSeconds | 4B | 今回の電源投入後の稼働時間。単位は秒、下位バイトが先 |
| 5 | RunMode | 1B | 現在の動作モード |
| 6 | SoftwareVersion | 1B | ソフトウェアバージョン番号 |
| 7 | BoardType | 1B | 基板の種類 |

`RunMode` の定義：

| 値 | 意味 |
| --- | --- |
| `0x00` | 通常動作 |

ハードウェアバージョンとソフトウェアバージョンは、上位 4 ビットがメジャーバージョン、下位 4 ビットがマイナーバージョンを表します。たとえば `0x21` は `2.1` を示します。現在のファームウェアのソフトウェアバージョンバイトは `0x37`、つまり `3.7` です。`BoardType` が `0x00` の場合は弓形基板、`0x01` の場合は直線形基板を示します。

## 11. 校正データと校正操作

校正するときは、センサーを背景色に合わせて取得し、次にライン色に合わせて取得してから保存します。取得コマンドは、送信時点の測定値を読み取ります。

### 11.1 保存済みの校正データを照会する

コマンド `0x05` を送信します。要求の Payload は空です。

```text
AA 05 00 02 E0 BB
```

デバイスはコマンド `0x85` を返します。Payload の長さは 33 バイトです。

| オフセット | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 0-15 | High[0..7] | 16B | 8 チャンネルの高値校正データ。各チャンネル 2 バイト、リトルエンディアン |
| 16-31 | Low[0..7] | 16B | 8 チャンネルの低値校正データ。各チャンネル 2 バイト、リトルエンディアン |
| 32 | LineType | 1B | `0x00`：背景色が高値、ライン色が低値。`0x01`：背景色が低値、ライン色が高値 |

### 11.2 背景色を取得する

センサーを背景色に合わせてから、コマンド `0x06` を送信します。

```text
AA 06 00 02 10 BB
```

成功すると、デバイスはコマンド `0x86`、Payload 長 `0x01`、Payload `00` を返します。現在露出過多であるか、校正がロックされている場合は、エラーコード `0x05` を返します。

### 11.3 ライン色を取得する

センサーをライン色に合わせてから、コマンド `0x07` を送信します。8 チャンネルすべてを一度に取得することも、2 回に分けて取得することもできます。

| 取得範囲 | 要求フレーム全体 |
| --- | --- |
| 全 8 チャンネル | `AA 07 00 03 80 BB` |
| 前半 4 チャンネル（チャンネル 0-3） | `AA 07 01 01 00 51 BB` |
| 後半 4 チャンネル（チャンネル 4-7） | `AA 07 01 02 40 50 BB` |

直線形基板では、全 8 チャンネルを一度に取得できます。弓形基板では前半の 4 チャンネルを取得し、その後で後半の 4 チャンネルを取得します。片方だけでは保存できません。1 バイトの Payload `00` も、全 8 チャンネルの取得を示します。

成功すると、デバイスはコマンド `0x87`、Payload 長 `0x01`、Payload `00` を返します。取得時に露出過多であるか、校正がロックされている場合はエラーコード `0x05`、範囲値が無効な場合は `0x03` を返します。

### 11.4 校正データを保存する

背景色とすべてのライン色の取得が完了したら、コマンド `0x08` を送信します。

```text
AA 08 00 06 70 BB
```

成功すると、デバイスはコマンド `0x88`、Payload 長 `0x01`、Payload `00` を返します。取得が不完全な場合はエラーコード `0x03`、校正がロックされている場合は `0x05` を返します。保存後は `0x05` を再送信して校正データを照会できます。

## 12. デバイスの再起動

コマンド `0x10` を、Payload `01` で送信します。

```text
AA 10 01 01 B0 55 BB
```

デバイスはまずコマンド `0x90`、Payload `00 01` を返し、その後に再起動します。再起動中はシリアルポートが一時的に使用できなくなります。デバイスの準備が整ったら PING を送信できます。

## 13. リアルタイムデータストリーム

リアルタイムデータストリームでは、デバイスが一定周期でセンサーデータを自発的に出力します。

リアルタイムデータストリームは標準フレーム形式を使用せず、固定長のデータフレームを使用します。

### 13.1 リアルタイムデータストリームを開始または更新する

ホストが送信：

```text
DD Interval
```

| バイト | 説明 |
| --- | --- |
| `DD` | リアルタイムストリーム制御ヘッダー |
| `Interval` | 1 バイトの出力間隔。単位はミリ秒です。ゼロ以外はリアルタイム出力周期の開始または更新、`00` はストリーム出力の停止を示します |

例：

```text
DD 0A
```

リアルタイムデータストリームを開始し、10 ms 間隔で出力します。

### 13.2 リアルタイムデータストリームを停止する

ホストが送信：

```text
DD 00
```

`Interval` が `0x00` の場合、デバイスはリアルタイムデータストリームを停止します。ストリームの動作中、デバイスは通常の照会要求と校正要求を処理しません。これらの要求を送る前に `DD 00` を送信してストリームを停止してください。

### 13.3 リアルタイムデータフレームの形式

デバイスは固定長 21 バイトのデータフレームを出力します。

```text
DD Digital Analog[0] ... Analog[7] Normal[0] ... Normal[7] Offset_L Offset_H EE
```

| オフセット | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 0 | フレームヘッダー | 1B | 固定値 `0xDD` |
| 1 | Digital | 1B | 8 チャンネルのデジタル出力ビットマップ |
| 2-9 | Analog | 8B | 8 チャンネルのアナログ値。各チャンネル 1 バイト |
| 10-17 | Normal | 8B | 8 チャンネルの正規化値。各チャンネル 1 バイト |
| 18-19 | Offset | 2B | オフセット。符号付き 16 ビット整数で、下位バイトが先 |
| 20 | フレーム終端 | 1B | 固定値 `0xEE` |

### 13.4 リアルタイムデータストリームの解析時の注意点

- リアルタイムデータフレームの長さは固定の 21 バイトです。
- リアルタイムデータフレームには Command、Length、CRC フィールドがありません。
- リアルタイムストリームを解析するときは、フレームヘッダー `0xDD` とフレーム終端 `0xEE` を探し、長さが 21 バイトであることを確認してください。
- ストリーム内の `Digital`、`Analog`、`Normal`、`Offset` フィールドは、センサーデータ照会応答にある同名のフィールドと同じ意味です。

## 14. エラー応答

デバイスが未対応のコマンド、誤った長さ、無効なパラメーターを受信したときや、校正中に露出過多が発生したときは、エラー応答を返す場合があります。

エラー応答は標準フレーム形式を使用します。

| 項目 | 値 |
| --- | --- |
| Command | `0x7F` |
| Length | `0x02` |
| Payload | 元のコマンドコード + エラーコード |

Payload のフィールド定義：

| オフセット | フィールド | 長さ | 説明 |
| --- | --- | --- | --- |
| 0 | OriginCommand | 1B | エラーを引き起こした元のコマンドコード |
| 1 | ErrorCode | 1B | エラーコード |

エラーコードの定義：

| エラーコード | 意味 |
| --- | --- |
| `0x01` | 未対応のコマンド |
| `0x02` | データ長の誤り |
| `0x03` | パラメーター値の誤り |
| `0x04` | 実行失敗 |
| `0x05` | 校正データ取得時の露出過多、または校正のロック |

例：

```text
Command = 7F
Payload = 99 01
```

これはコマンド `0x99` が未対応であることを示します。

## 15. フィールドとバイト順

### 15.1 16 進数表記

この文書ではバイトを 16 進数で表します。例：

```text
AA 01 00 00 20 BB
```

これは、`0xAA`、`0x01`、`0x00`、`0x00`、`0x20`、`0xBB` の 6 バイトを順に送信することを示します。

### 15.2 複数バイトのフィールド

複数バイトのフィールドはリトルエンディアンです。下位バイトが先、上位バイトが後になります。

たとえば `Offset` の元のバイトが次の場合：

```text
34 12
```

次のように解析します。

```text
0x1234
```

### 15.3 標準フレームの解析手順

標準フレームは次の順序で解析することを推奨します。

1. フレームヘッダー `0xAA` を探す。
2. `Command` を読み取る。
3. `Length` を読み取る。
4. `Length` で指定された長さの `Payload` を読み取る。
5. 2 バイトの CRC を読み取る。
6. フレーム終端が `0xBB` であることを確認する。
7. `Command + Length + Payload` の CRC を計算し、受信した CRC と比較する。
8. CRC が正しければ、コマンドコードに従って Payload を解析する。

### 15.4 リアルタイムストリームの解析手順

リアルタイムデータストリームは次の順序で解析することを推奨します。

1. フレームヘッダー `0xDD` を探す。
2. 連続する 21 バイトを読み取る。
3. 21 バイト目がフレーム終端 `0xEE` であることを確認する。
4. 固定オフセットに従って `Digital`、`Analog`、`Normal`、`Offset` を解析する。

## 16. よくある質問

### 16.1 `CC` を送信しても応答がないのはなぜですか？

次の点を確認してください。

- シリアルポート番号は正しいか。
- ボーレートは `115200` か。
- データ形式は `8N1` か。
- TX/RX が逆に接続されていないか。
- デバイスに正常に電源が供給されているか。

### 16.2 標準フレームに応答がないのはなぜですか？

次の点を確認してください。

- フレームヘッダーは `AA` か。
- フレーム終端は `BB` か。
- Length は実際の Payload の長さと等しいか。
- CRC は `Command + Length + Payload` から計算したか。
- CRC の下位バイトを先に送信しているか。

### 16.3 照会とリアルタイムストリームはどう使い分けますか？

- データを時々 1 回だけ読み取る場合：センサーデータ照会を使用します。
- 連続表示やグラフ描画が必要な場合：リアルタイムデータストリームを使用します。
- デバイスが接続されていることを確認する場合：PING を使用します。
